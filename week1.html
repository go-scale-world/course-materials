Part A

What Is AI, and What Is Agentic AI?

Definition — AI, really

AI is technology that lets a computer act like it understands things, even though it does not really think or feel like a human. It copies human behaviour, such as talking, recognising patterns, or making decisions.

There are two well-known definitions used to describe AI:

  • Merriam-Webster's Dictionary: AI is the ability of a computer system to copy intelligent human behaviour, such as understanding language, recognising patterns, or making decisions.
  • IBM: AI is technology that lets computers simulate human learning, understanding, problem solving, decision-making, and creativity, instead of just following fixed instructions.
  • AI does not think or feel — it only acts in ways that look intelligent.
  • It can understand language, spot patterns, and make decisions.
  • It replaces "fixed instructions" (simple step-by-step programs) with behaviour that looks like learning and reasoning.

Generative AI (Gen AI) — The AI We Already Know

Definition: Generative AI is the kind of AI most people already use. You ask it something, and it answers — every single time you ask.

✎

Write

Emails, messages, stories, code.

≡

Summarize

Turns long articles into short ones.

?

Answer

Like a friend who has read a lot and can answer questions.

</>

Generate Code

You describe what you want, and it writes the code.

Example: If you ask a chatbot to write an email for you, it writes it immediately. But it will not send it — that part is still up to you.

The Gap — What Gen AI Can't Do

Even though Gen AI is useful, it has clear limits:

  • Can't act on its own — it can tell you how to send an email, but it will not send it for you.
  • Can't break a big task into steps — it answers a complex request all at once instead of working through it piece by piece.
  • Doesn't check its own work — a mistake stays there unless a person points it out.
  • Always waits — it never acts by itself; it waits until you type the next instruction.
🧠 Key idea

Gen AI is like a helpful pen, not a helpful worker. A pen can write down what you tell it, but it cannot pick itself up and get things done.

Agentic AI — Basic Definition

Definition

Agentic AI is a system that can decide, act, and work toward a goal, needing less step-by-step help from a person than regular Gen AI does.

Agentic AI starts exactly where the "Gen AI gap" ends. Instead of just answering one prompt, it plans a path toward a goal, takes actions, and only asks a human when needed — usually for approval.

Gen AI vs Agentic AI

FeatureGen AIAgentic AI
How it worksOne prompt at a timeMultiple steps toward a goal
MemoryForgets past stepsRemembers and reuses information
ActionOnly describes what to doActually does it
DecisionsMakes none, just respondsMakes small decisions along the way
Human roleNeeded at every stepNeeded mainly for approval

Key Point: Neither one is "bad." Agentic AI is simply Gen AI with more responsibility added to it.

Part B

Agentic AI in Real Companies

The deck shows five real examples of agentic AI being used inside big companies. Each one follows a similar pattern: Think → Search → Do → Connect, and for team-based systems: Teamwork → Improve.

1. Customer Support Resolution Agent — Klarna Klarna+
The customer asks a question → the AI understands it → checks customer and order data → answers or solves the problem → escalates to a human if needed.
2. Sales Intelligence Agent Salesforce+
A customer or company is identified → the AI researches data → finds an opportunity → suggests the next action → the salesperson acts on it.
3. Financial Fraud Detection JPMorgan Chase+
A transaction happens → the AI checks the behaviour → spots anything unusual → gives a risk signal → the bank investigates or blocks it.
4. HR Recruitment Agent Unilever+
An application arrives → the AI assesses the candidate → screens candidates → candidates move through assessment → the recruiter makes the final decision.
5. Supply Chain and Procurement Agent Walmart+
Stock or demand changes → the AI predicts what is needed → checks the supply → recommends an action → the order or restocking happens.
Key points — the pattern behind all of them
  • The agent starts by Thinking about the request.
  • It goes Searching through business or customer data.
  • It keeps Doing the real task (for example, scoring a risk).
  • It stays Connecting to the company's real systems the whole time.
  • For bigger jobs, several agents work as a Team, each handling one part.
  • Every result — accepted or corrected — helps the system keep Improving over time.

These examples matter because the AI works inside real business steps, not just generating text.

Part C

The Six Building Blocks of an Agent

Every agent in this course is built from the same six concepts.

1. LLM — "Thinking"+

Definition: The LLM is the part of the agent that thinks. It reads text, understands what you want, and decides what to do next.

Examples: Gemini, Claude Sonnet 5, GPT.

2. Tooling — "Doing"+

Definition: Tooling is the set of abilities given to the agent so it can search, look things up, or take an action.

Examples: Function calling, search tools, APIs.

3. RAG — "Searching"+

Definition: RAG is a way to check real facts before answering. The agent does not rely only on what it remembers from training — it looks things up first.

Examples: Vertex AI Vector Search, text embedding models.

4. Multi-Agent Architecture — "Teamwork"+

Definition: A team of smaller agents, where each one has its own job, and they work together to finish a bigger task.

Examples: Cloud Workflows, LangGraph.

5. MCP — "Connecting"+

Definition: MCP is a common, standard way for an agent to connect to outside tools and data sources.

Explanation: Instead of every company building a custom connector for every tool, MCP gives one shared way to plug an AI model into external systems (like a database, a file, or a company API), so different tools and different AI models can talk to each other more easily.

Examples: Model Context Protocol servers.

6. Feedback — "Improving"+

Definition: Feedback is information that helps the agent do better the next time. Examples: Human review, approval, or rejection.

A Simple Agent Example: The Discord Helper

Problem: Students ask course questions in a Discord server all day. Someone has to answer every question, even repeated ones.

How the agent works:

  1. A question comes in on Discord.
  2. The agent checks the courseInfo file for the answer.
  3. If found: the Gemini LLM writes the answer.
  4. If not found: the agent declines honestly — "I am a Scale course assistant" — instead of guessing.
🧠 Key point

This is agentic behaviour in miniature — the agent Thinks about the question, Searches the file for an answer, and only then Does the reply (either answering or honestly declining).

When is this used? Whenever a company receives a bill from a vendor or supplier and needs to check and pay it correctly.

The problem, before AI:

  1. A finance employee opens every invoice by hand.
  2. They retype the details into the finance system.
  3. They dig through paperwork to find the matching purchase order.
  4. They check the math and rules themselves, invoice by invoice.
  5. With thousands of invoices a day, the team simply cannot keep up — mistakes slip through and payments get delayed.

The AI-powered workflow (10 specialised agents, each with one job):

Intake → Extraction → Procurement → Goods Check → Finance → Compliance → Decision → Payment → Human Review → Monitoring

  1. Intake Agent: reads the invoice and sends it down the right path (LLM).
  2. Extraction Agent: pulls out vendor, amount, and items (LLM).
  3. Procurement Agent: matches the invoice to the purchase order (RAG and MCP).
  4. Goods Verification Agent: checks that the goods arrived (APIs and MCP).
  5. Finance Agent: checks the math, tax, and terms (LLM reasoning).
  6. Compliance Agent: checks it against company policy (RAG and guardrails).
  7. Decision Agent: approves, rejects, or sends for review — coordinates every other agent.
  8. Payment Agent: starts the payment if approved (tools and APIs).
  9. Human Review Agent: a person steps in if something looks off.
  10. Monitoring Layer: logs every action so the whole process can be checked.
Key point

Instead of one agent doing everything, ten specialised agents work as a team — this is Multi-Agent Architecture in action.

When is this used? Whenever a support team gets many tickets and needs to notice when several customers are reporting the same underlying problem.

The problem, before EPC:

  1. Customers report the same bug through many different tickets.
  2. A support agent answers each ticket on its own, one at a time.
  3. Nobody connects the tickets to see a pattern forming.
  4. It takes a human noticing, by chance, that this keeps happening.
  5. By then, hundreds of customers may already be affected — a small issue can quietly grow into a major outage.

The EPC workflow (7 steps, from a raw ticket to a final, reviewed result):

collecting_details → info_extraction → making_groups → saving_group → impact_scoring → report_prep → final_result

  1. collecting_details: saves the new ticket's basic details (ID, text, source). Nothing is sent out yet.
  2. info_extraction: sends the ticket text to a helper service, which pulls out the real meaning and urgency. Tries again if it fails.
  3. making_groups: sends the ticket ID to a service that checks for other tickets about the same problem, and groups them.
  4. saving_group: saves the group ID that came back, so later steps can use it. Does not call any service.
  5. impact_scoring: sends the group ID to a service that looks at the whole group and scores how serious it is.
  6. report_prep: sends the group ID to a service that decides if a person should review it, and prepares a short report.
  7. final_result: gathers the ticket ID, group ID, and review status, and returns it as the final result.

Prompt Building

Running example used in this section: an AI that generates study notes (the same task these notes were made with!).

The CREATE Framework

A good prompt is built from six parts. If you skip a part, something predictable goes wrong.

LetterPartHowWithout it
CCharacterGive the AI a role, like "You are a helpful assistant."The AI has no identity, so its tone and behaviour can drift or feel generic.
RRoleState the exact job it does, like turning topics into notes.The AI may do the wrong kind of task, or mix up what it should produce.
EExampleShow one sample input and output.The AI guesses the format, and results come out inconsistent every time.
AAdjustmentSet limits, like simple language or a word count.Output can be too long, too complex, or miss what the request needed.
TToneSet the voice, like friendly and clear.The tone can feel cold, robotic, or wrong for the audience.
EExtraPlan for edge cases, like a topic that is too broad.The AI may guess instead of asking, and give a bad answer with confidence.

The Final Prompt, Built With CREATE

You are a helpful assistant. Your exact role is a note-making assistant that turns any topic I give into clear notes. For example, Topic: Photosynthesis, Output: Definition, Key Points, and Example. Keep the language simple, use 3 to 5 key points only, and avoid hard words. Use a friendly and clear tone that is easy for a student to read. If the topic is too broad, ask me to narrow it down first. Topic: [topic text]

Key Point: Notice how each CREATE part (Character, Role, Example, Adjustment, Tone, Extra) maps directly onto one sentence of the final prompt.

System Prompt vs User Prompt

FeatureSystem PromptUser Prompt
MeaningThe rules, set ahead of timeThe actual ask, right now
Example"You are a note-making assistant. Your only task is to turn any topic I give you into clear notes. Always include a short definition, three to five key points, and one simple example. Keep the language simple.""Photosynthesis."
ReuseSets the AI's behaviour for every request that followsReused with the same system prompt every time — nothing extra is needed since the system prompt already set the rules
Part F

Core AI Knowledge

LLM Fundamentals

Definition

An LLM (Large Language Model) is a program trained on huge amounts of text. It does not think like a person — it predicts the next word, one piece at a time, based on patterns it learned.

Key Points (the four building blocks of an LLM):

Training+
The learning phase. The process of showing the model huge amounts of text so it learns language, facts, and patterns. Examples: books, websites, and code.
Tokens+
Word pieces. Small pieces of text, like parts of a word. The model reads and writes text one token at a time. Example: "un" + "happy" makes "unhappy."
Parameters+
The model's internal settings, learned during training. More parameters usually means the model can understand more complex patterns. Examples: billions to trillions of parameters.
Context Window+
The memory size. How much text the model can see and remember at once, in a single conversation. Examples: from a few thousand to millions of tokens.

SLM: Small Language Models

Definition

An SLM is a smaller version of an LLM. It has fewer parameters, so it needs less computing power, but it is still trained to understand and write language.

FeatureLLMSLM
SizeVery large, billions of parametersSmaller, millions to a few billion parameters
SpeedSlower, needs more computing powerFaster, needs less computing power
Where it runsMostly in the cloud, on big serversCan run on a phone or laptop
Best forComplex reasoning, broad knowledgeSimple, fast, focused tasks
CostMore expensive to runCheaper to run
ExamplesGemini, Claude Sonnet 5, GPTGemma, Phi, Claude Haiku

Schema Validation

Definition

A schema is the required "form" for an AI's output. Every response is checked against it before it is trusted.

Explanation: When an agent produces output (for example, study notes), the system checks whether every required field is actually present. If something is missing, the output is rejected and the agent tries again, instead of passing along an incomplete result.

Example — Required fields for a "Notes" output:

FieldStatus
Title✓ Present
Definition✓ Present
Key Points (list)✕ Missing → Reject and try again
Example✓ Present
  • It catches bad data early.
  • It keeps output consistent every time.
  • It builds trust — the system checks the work instead of just hoping it is right.

Coded Agents vs No-Code Agents

Explanation: No-code tools are great for quick, simple automation. But once real-world limits (security, scale, custom rules) show up, the gap between no-code and coded agents becomes clear.

This is one reason coded agents are a skill worth learning — people who build coded agents sit at the crossing point of AI, software engineering, and business.

Part G

Lab Session — Building the EPC Pipeline

Approaches to Developing Agentic AI With Code

There are four common ways to build an agent, from the fastest to the most flexible:

Framework Orchestration

Compose multiple agents into graphs or chains that plan, coordinate, and hand off tasks to one another. Examples: LangGraph, CrewAI, AutoGen.

Agent SDKs

Vendor-provided SDKs that ship with built-in tool-use, memory, and orchestration out of the box. Examples: Google ADK, Semantic Kernel, OpenAI SDK.

Low-Code Builders

Visual, drag-and-drop builders for assembling and testing agents fast, with minimal hand-written code. Examples: Vertex Agent Builder, Flowise, Langflow.

Custom Code

Full control — build agent logic from scratch on top of core libraries and your own architecture. Examples: LangChain, LlamaIndex, Raw APIs. Built in Python, TypeScript/JS, Java, and Go.

Open-Source Framework vs Enterprise GCP Stack

There are two different paths to building and running agentic AI:

Open-Source Framework
  • Uses community-built libraries like LangChain, LangGraph, or CrewAI.
  • You self-host, wire up infrastructure, and manage scaling yourself.
  • Highly flexible and fast to prototype with.
  • Security, compliance, and support are on you.
  • Best fit: rapid prototyping and full control.
Enterprise GCP Stack
  • Built on Vertex AI and Agent Builder, backed by Google Cloud.
  • Fully managed infrastructure that scales automatically.
  • Enterprise-grade IAM, security, and compliance built in.
  • Native integration with your GCP data and AI services.
  • Best fit: production-scale, regulated environments.

Building the First Part of the EPC Pipeline

Key idea

To begin any AI workflow, the first step is feeding the AI good information — data it can actually analyse and use to make smarter decisions.

Explanation: Before any smart decision can be made, a messy support problem must first be converted into a clean, structured format. That structure flows down the whole pipeline — every decision made after this step is built on this foundation.

From Inbox to Raw JSON

When a new email arrives, it is first captured in a simple, consistent structure (JSON), before anything is understood about it:

{
  "ticket_id": "T040",
  "raw_text": "Hi team, every few minutes I'm getting logged out of my account even though I'm actively using the app. It's becoming impossible to finish my work.",
  "source": "email",
  "timestamp": "2026-02-10T09:15:00Z"
}
  • ticket_id — a unique ID for the ticket.
  • raw_text — the customer's original message, unedited.
  • source — where the ticket came from (here, email).
  • timestamp — when the ticket arrived.

At this stage, the ticket is just raw text — the system does not yet know what the problem is about.

From Structured JSON to Database

After the agent processes the raw ticket, it enriches it with meaning before it is stored:

{
  "product_area": "Login",
  "issue_type": "Access Issue",
  "urgency": "Critical",
  "region": "Unspecified",
  "summary": "The user is repeatedly logged out of their account while actively using the application, making it impossible to complete work.",
  "ticket_id": "T040"
}
  • product_area and issue_type — tell the system what part of the product is affected and what kind of problem it is.
  • urgency — how serious the problem is (here, "Critical").
  • summary — a short, clear restatement of the customer's problem, written by the agent.
  • This enriched version is what actually gets saved to the database — not the raw text alone.
