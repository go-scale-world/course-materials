Part A

What Is a Single Agent?

Monolithic Boundary

A single agent is an AI system that handles a task from start to finish within a monolithic boundary. All reasoning, planning, and decision-making occur internally without external coordination.

Workflow Analogy

Think of it as a single employee managing a complete workflow end-to-end without handing off any part of it.

Example: A basic FAQ chatbot receives a query, searches its internal database, and generates a response — narrow and self-contained.

Part B

Single Agent Limitations

Single-agent architectures excel at small, isolated, and highly predictable tasks. However, as task complexity, volume, and scope scale, monolithic designs experience severe engineering strain.

Tool Overload Decision Space Limits+
The agent's decision space becomes too broad as too many tools are registered, causing selection errors and API invocation failures.
Context Exhaustion Memory Degradation+
As interaction volume and scope scale, the model reaches its context window limit, leading to dropped details, memory truncation, and lost state.
Reasoning Collapse Error Propagation+
A critical lack of independent external verification allows minor errors to multiply unchecked, resulting in complete task derailment.
Part C

What Is a Multi-Agent System (MAS)?

Decentralized Task Division

Divides complex workflows into smaller, specialized sub-tasks distributed across a team of distinct, independent agents.

The Central Orchestrator

Coordinates actions, schedules tasks, and routes data across the ecosystem, ensuring no single agent holds the entire task context.

Analogy

Like a corporate office with specialized roles, parallel agents (pricing, reviews, news) collaborate to synthesize one master report.

Part E

Core Components of a Multi-Agent System

A working multi-agent system generally has five parts.

1. Specialized Agents+

Definition: An agent built to do one job well, with its own instructions and tools focused on that job, rather than trying to do everything.

Analogy: In a hospital, a cardiologist treats hearts and a dentist treats teeth. Both are doctors, but neither is expected to do the other's job.

Example — a finance team: Reader Agent extracts vendor, amount, and date. Validation Agent checks completeness and consistency. PO Agent matches the invoice to an existing purchase order. Approval Agent decides whether it can be approved under company policy. Each agent stays within its own job.

2. Orchestration and Coordination+

Definition: The layer that decides the order of work, passes information between agents, and handles failures. Without it, a group of agents has no shared workflow.

Analogy: A project manager who does not do the work personally, but decides who does what, in what order, and what happens once each part is done.

Example — the same finance team: An Orchestrator sits above the invoice team, sending a new invoice to the Reader, then Validation, then PO, then Approval Agent, in that order. Once approval is decided, it stores the final result. The Orchestrator itself does not read invoices or approve payments.

3. Communication Protocols+

Definition: The standard ways agents talk to tools and to each other. Two common types:

  • MCP (vertical communication): connects an agent downward to outside tools and data, such as a database or an API.
  • A2A (horizontal communication): lets one agent talk sideways, directly to another agent at the same level.

Analogy: MCP is like an employee calling down to a filing room to pull a record. A2A is like that same employee turning to a colleague at the next desk and handing off part of the work directly.

4. Memory and Shared State+

Definition: A shared, common record that all agents read from and write to, so agents are not each relying on their own separate, possibly outdated view of the same information.

Example — an e-commerce company: A Warehouse Agent tracks stock levels and a separate Order Agent processes purchases. If each kept its own private copy of the stock count, the Order Agent could accept an order for a sold-out item because its copy hasn't caught up. A single shared stock record, checked by both before they act, prevents this mismatch.

5. Tools+

Definition: The outside systems an agent uses to take action, such as databases, APIs, or internal software, rather than only reasoning about a task.

Analogy: An accountant still needs accounting software, and a mechanic still needs a wrench. Knowing what to do is not the same as being able to do it.

Example — a finance team: An Approval Agent uses an internal Approval Rules API to check whether an invoice amount falls within a manager's spending limit. Without that tool, the agent would know the rule exists but could not check it against real numbers.

Architectural Orchestration Patterns

Orchestration patterns define the systemic topology and control flows that govern how agents pass state, wait for subprocesses, and select next actions.

Linear & Ordered Pipeline

Rigid Execution Pipeline: enforces strict, linear execution where each agent waits for upstream outputs. Strong data dependencies prevent subsequent steps from being bypassed, ensuring high-fidelity outputs through a structured chain of custody.

Key architectural benefit: guarantees systematic validation. No downstream service executes until all predecessor dependencies pass complete schema and business logic checks.

Concurrent Execution

Multiple agents work on different, independent parts of a task at the same time. Their results are combined once all agents finish.

Classification & Routing

The Router Pattern utilizes a specialized classifier agent to evaluate incoming requests and dynamically route them directly to the most qualified expert agents. Unlike hierarchies, the router focuses strictly on categorization and delegation without supervising or co-authoring the response pipeline.

Application: ideal for customer support triage — analyzing user intent to instantly dispatch billing issues to Finance and bug reports to Tech Support.

Utilizes a parent Supervisor Agent that receives a high-level goal, decomposes it into discrete sub-tasks, and assigns them to specialized worker agents. The supervisor coordinates execution and synthesizes the final outputs into a cohesive response.
